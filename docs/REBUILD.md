# wya: rebuild specification

_Written 2026-10-17; updated 2026-10-17 for Phase 8.0–8.2 and the Glow redesign. The source for a design doc to
rebuild wya from scratch with the same functionality._

**Scope**
- **Core spec:** everything built today: Phases 0–7, plus Phase 8.0 (typed chat messages, rate limits), 8.1 (invite
  limits and approve-to-join) and 8.2 (slash commands and polls), and the **Glow** redesign (design-board look, Home
  dashboard). 8.0–8.2 and Glow are on the `phase8a-core` branch, applied to wya-dev.
- **Later milestone:** the rest of the Phase 8 "smart coordination" plan, 8.3–8.17 (`docs/PHASE8.md`).
- **Stack:** the same one (Expo + React Native + Supabase).
- **Justification:** every data and architecture decision is tied to the use case it serves.

**Sources:** all 16 migrations in `supabase/migrations/`, every client file, and the docs (`docs/PLAN.md`,
`docs/FEATURES.md`, `docs/PHASE5–8.md`, `CLAUDE.md`). When this file and the migrations disagree, the migrations win.

**Deviations:** section 12 lists the few places where a rebuild should deliberately improve on the current build.
Nothing else changes behaviour. The repo's own source of truth is unchanged; this document describes it.

---

## 1. Product

**Problem.** Hosts over-prepare for guests who flake: invite 30, cook for 30, 10 show up.

**Core loop.** On a pledge event, "I'm in" means "if I don't show, I'll pay the host $5".
- Show up, and nothing happens.
- Flake (no-show, or cancel after the cutoff) without an excuse the host accepts, and you pay the host **directly by
  PayID**.
- **wya never touches money**, which keeps out payment friction, fees and licensing.

**Supporting features.** Everything else is "the one place for the event": invites, guest list, chat, album, Activity.
Each one exists to make the commitment stick.

**Market.** Australia first, which is why the payment method is PayID. Other regions later, with one payment-provider
file each. The strongest paying segment later is clubs and societies; casual friend groups drive the viral spread.

**Principles**
1. Least friction: no ID checks, no card forms, no waiting.
2. Rules are enforced in the database, not the app.
3. Build to extend: `deposit_mode`, one debt lifecycle, one payment-provider file per method.
4. Web is first-class, because guests meet wya through a link.
5. Nothing public: invite-only.

**Voice.** Sentence case, plain and friendly: "Plans that actually happen.", "Are you coming?", "I'm in", "You owe
Hannah $5". The UI is honest about limits; for example, it never pretends a PayID link pre-fills a bank app.

**Business model.** Free while proving pledges work. wya can't take a cut of PayID transfers, and that's intentional.
Later options: per-event upgrades, paid SMS reminders, a clubs and organisations tier. Not doing: ads, selling data, or
charging around reliability records.

## 2. Architecture and stack (each choice justified)

| Layer | Choice | Why (use case) | Alternative considered |
|---|---|---|---|
| Client | **Expo SDK 57, React Native 0.86, React 19, TypeScript, Expo Router** | One codebase for iOS, Android and web. File routes give real URLs (`/invite/<code>`, `/event/<id>`) for web links and deep links. Two founders can't maintain three apps | Separate native apps plus a Next.js web app: three times the work |
| Native folders | **Generated by prebuild (CNG)**; `ios/` and `android/` are git-ignored | Native config lives in `app.json` and is reproducible; nobody hand-edits Xcode projects | Committed native folders: drift and merge pain |
| Backend | **Supabase**: Postgres, RLS, Auth, Storage, Realtime, pg_cron | Data is relational (events ↔ RSVPs ↔ debts ↔ photos). Money-adjacent state machines need constraints, triggers and transactions. RLS puts every rule in one place the web, native, tests and the future assistant all hit. No server to run | Firebase: weak at relational joins and multi-row rules. A custom API server: more to run and secure |
| Business logic | **Postgres functions (RPCs, `security definer`, `search_path=''`) and triggers** | RLS can't hide columns per viewer and can't express multi-step rules (pledges, caps, attendance). Functions run atomically with row locks and are testable over HTTP | App-side logic: bypassable, and duplicated across platforms |
| Auth | **Email and password**; a database trigger creates the profile from sign-up metadata | Lowest friction. The profile always exists, with no client race | Magic links / OAuth: extra redirects. Later option |
| Files | **Storage**: two public buckets plus one private album bucket | Covers and avatars are fine as public, unguessable URLs. Party photos need privacy (1-hour signed links) | All private: signing every image adds latency for little gain |
| Live updates | **Realtime `postgres_changes`** on chat, notifications and photos | Chat must be live; badges must update; the album fills up during the party | Polling: laggy and wasteful |
| Scheduling | **pg_cron** every 15 minutes | Maybe reminders and auto-expiry at the cutoff without a server | An external cron service: another secret and another moving part |
| Web hosting | **EAS Hosting**, `web.output: "single"` (SPA) at `wya.expo.app` | Free, and comes with Expo. Link-preview tags are injected after export | Server output: needed later for per-event link previews |
| Marketing site | Separate **Next.js static export** (`website/`), Vercel Analytics (cookieless), Google Form waitlist | No backend, no keys, nothing to leak; separate release cadence | Inside the app: ties marketing to app releases |
| Phase 8 only | **Supabase Edge Functions** (Deno) | Anything needing secrets: the LLM, Places API, push | Client-side keys: leak |

**Client libraries and why**

| Library | Use case |
|---|---|
| `@supabase/supabase-js` | Data, auth, storage and realtime client |
| `expo-secure-store` | Sessions on phones, chunked for its 2 KB limit |
| AsyncStorage | Theme and list preferences |
| `expo-image` | Disk-cached, fast images; `cacheKey` survives re-signed URLs |
| `expo-image-picker` + `expo-image-manipulator` | Pick photos, re-encode to strip GPS/EXIF, make thumbnails |
| `expo-file-system` | Reliable bytes on native, where `fetch().blob()` can be empty |
| `expo-media-library` | "Save photo" with add-only permission |
| `expo-clipboard` | Copy PayID and payment reference |
| `expo-haptics` | Feedback on taps, success and RSVP |
| `expo-crypto` | Client-generated photo ids, so the path is known before upload |
| Reanimated + Gesture Handler | Springs, confetti, entrances: the brand's motion |
| `@react-native-community/datetimepicker` | Native date and time pickers |
| `date-fns` | Formatting and cutoff maths display |
| Ionicons | Icons |
| `@expo-google-fonts` (Bricolage Grotesque, DM Sans) | Brand type |
| `expo-splash-screen`, `expo-system-ui` | Hold the splash until fonts load (phones); paint the root background per theme |
| `expo-build-properties` | `ios.enableSceneSupport: true`, needed for iOS 27 |

**Network policy** (`lib/supabase.ts`): retry **only GET and HEAD**, with a 15 s timeout, 3 tries and backoff. Writes
are **never** retried, because a retry could double-send an RSVP, a message or "I've paid".

## 3. Data model

All tables have RLS on. Money is stored in integer cents (AUD). Times are `timestamptz`. Section 4 covers who can read
and write each table.

### profiles
- **Use case:** your name, avatar and phone, shown to people you share an event with.
- **Columns:** `id` (PK, FK `auth.users` on delete cascade), `full_name`, `avatar_url`, `phone`, `created_at`.
- **Created by** the `handle_new_user` trigger on `auth.users` insert:
  - copies name and phone from sign-up metadata;
  - schema-qualified and `on conflict do nothing`, because the auth service's `search_path` broke the first version.

### events
- **Use case:** the plan itself.
- **Columns:**
  - `id`, `host_id` (FK `auth.users` cascade), `title`, `description`;
  - `date` (start) and `end_date`;
  - `venue_name`, `address` (not null, **not selectable**), `latitude`, `longitude`;
  - `dress_code`, `notes`, `cover_image` (public URL), `venue_images` (text[]), `contact_numbers` (text[]);
  - `created_at`.
- **Columns added for specific features:**

| Column | Purpose |
|---|---|
| `allow_guest_invites bool` (default true) | Host controls re-sharing |
| `theme text` | Check: lime, bubblegum, violet, tangerine, ocean, sunset; default random so new events vary; colours the cover, invite and stickers |
| `deposit_mode text` | `none` or `pledge`; `upfront` is reserved for option A |
| `deposit_cents int` | 100–5000, default 500 (R8: "a pledge, not a ticket price") |
| `cutoff_hours int` | 0–336, default 24. Stored relative, so the cutoff moves with the event (R1) |
| `max_guests int` (8.1) | 1–500 or null. Once that many say I'm in, "I'm in" is refused (`event_full`); Maybe isn't capped. A trigger locks the event row so two people can't take the last spot |

- **Column grant:**
  - `authenticated` may select every column **except `address`**; `anon` gets no select at all.
  - Why: the address is the reward for committing on pledge events (section 5.6), and RLS can't hide a column.
  - Consequences:
    - `select('*')` fails;
    - the app selects an explicit `EVENT_COLUMNS` list;
    - inserts ask only for `id` back;
    - **every new events column needs adding to the grant and to `EVENT_COLUMNS`**.

### event_invites
- **Use case:** the shareable link code.
- **Columns:**
  - `event_id` (PK, FK cascade);
  - `code` (unique, 12 hex characters, from a random uuid);
  - `created_at`.
- **Created by** the `on_event_created` trigger.
- **Why a separate table:** a column on `events` would be readable by every guest, but re-sharing is the host's choice.
  Codes come out only through `get_invite_code`.
- **Link limits (8.1):** `expires_at`, `max_uses`, `uses`, `requires_approval`, set by the host with `set_invite_limits`.
  Use case: a link forwarded into an 80-person group chat shouldn't flood a 12-person dinner, and on pledge events every
  Going guest is a pledge. Limits apply only to people joining for the first time; anyone already on the event can
  always reopen the link.

### event_personal_invites (8.1)
- **Use case:** a one-time link for one person (for texting someone; the SMS hand-off in 8.8 uses it).
- **Columns:** `code` (PK, 12 hex), `event_id`, `created_by`, `label`, `used_by`, `used_at`, `created_at`.
- Made by the host, or a guest while re-sharing is on (`create_personal_invite`, 50 a day). Personal links skip
  approval: they're single-use, so they can't spread. Readable by the host and the person who made it; no direct writes.

### rsvps
- **Use case:** each person's relationship to an event, which is also their access to it.
- **Columns:**
  - `id`, `event_id` (FK cascade), `user_id` (FK `auth.users` **and** a second FK to `profiles`, so the API can embed
    profiles);
  - `status`: `invited | requested | yes | no | maybe` (`invited` = opened the link, hasn't answered; `requested`
    (8.1) = opened a link that needs the host's approval, and is **not a guest** until let in);
  - `additional_details` (the guest's note to the host);
  - `created_at`; unique (`event_id`, `user_id`).
- **Pledge and attendance columns:**
  - `pledge_cents`: the amount agreed at "I'm in". It belongs to the RSVP, not the event, so R2, R3 and R4 work;
  - `attended`: null means unmarked, assumed came;
  - `attendance_marked_at`;
  - `maybe_reminded_at`.
- **Writes:**
  - rows are created **only** by `accept_invite`;
  - guests may update **only** `status` and `additional_details` (column grant). Otherwise a guest could repoint their
    row at another event;
  - status can't go back to `invited`;
  - someone `requested` can't change their own status (trigger, hint `join_pending`): only the host's `approve_join`
    moves them to `invited`.

### event_removed_guests
- **Use case:** a removed guest can't rejoin through the same link.
- **Columns:** (`event_id`, `user_id`) primary key, `removed_at`.
- No policies; reached only through `remove_guest` and `accept_invite`.

### chat_messages
- **Use case:** the event group chat, including cards (polls now; splits and plans later) and wya's own replies.
- **Columns:**
  - `id`, `event_id` (FK cascade);
  - `user_id` (FK users and profiles, so the sender can be embedded); null only for `bot`/`system` messages;
  - `kind` (8.0): `text | image | poll | split | plan | bot | system`, and `data jsonb` for cards;
  - `content` (nullable);
  - `image_path`: a storage path, not a URL, so the database can check it's the sender's own upload and it survives a
    project-URL change;
  - `created_at` (set by the server).
- **Checks:**
  - every message has a body: text or image for `text`/`image`, text for `bot`/`system`, `data` for cards;
  - only `bot`/`system` have no sender, and they never have one;
  - `image_path` must match `^chat/<user_id>/[^/]+$`.
- **Writes:** clients insert only `text`/`image`, and only the columns `event_id, user_id, content, image_path, kind`
  (column grant), so they can't fake a card or backdate a message. Cards are posted by security-definer functions
  through `private.post_message`; wya's replies only through `post_bot_message`, which only the service role can call.
- Index on (`event_id`, `created_at desc`). Messages can't be edited or deleted by clients; a poll's `data.closed` is
  set by `close_poll`.

### poll_votes (8.2)
- **Use case:** votes on a poll card; one row per person per option, so votes arriving at the same moment can't
  overwrite each other (a jsonb counter could).
- **Columns:** (`message_id`, `user_id`, `option_id`) primary key, `event_id` (copied from the message so the policy
  and the live-update filter need no join), `created_at`.
- Readable by anyone who can chat in the event; no direct writes (`vote_poll` replaces your votes).

### private.rate_limits (8.0)
- **Use case:** limits shared by polls, personal links and (later) the assistant: fixed windows per key, via
  `private.hit_rate_limit(key, max, window)`, which raises with hint `rate_limited`. A daily cron job clears old rows.

### chat_reads
- **Use case:** unread counts per chat.
- **Columns:** (`user_id`, `event_id`) primary key, `last_read_at`.

### notifications
- **Use case:** the Activity feed and the bell badge.
- **Columns:**
  - `id`, `user_id` (recipient), `type` (17 values, section 5.8);
  - `event_id` (FK **on delete set null**, so "cancelled" survives the deletion);
  - `actor_id` (set null);
  - `data jsonb`: the title, actor name and so on, **denormalised at write time**, because profiles stop being visible
    after you no longer share an event;
  - `read_at`, `created_at`.
- Index on (`user_id`, `created_at desc`).
- Rows are written **only by triggers**; users may update only `read_at` (column grant). Users can't delete their
  notifications (a product rule).

### payment_methods
- **Use case:** the host's PayID, set once and used for every pledge event (D1).
- **Columns:**
  - (`user_id`, `provider`) primary key; `provider` is checked against the list `payid`;
  - `value` (normalised);
  - `created_at`, `updated_at`.
- **Writes only through `set_payid` and `remove_payid`**, which validate.
- Others read it only through `get_payment_instructions`, and only while they owe that person.

### obligations
- **Use case:** one ledger of who owes whom, with one lifecycle.
- **Columns:**
  - `id`, `event_id` (FK **cascade**: deleting an event forgives its debts, R12), `guest_id`, `host_id`;
  - `amount_cents` (> 0), `currency` (AUD);
  - `reason`: `no_show | late_cancel`;
  - `status`: `owed | excuse_pending | paid | waived | disputed`;
  - `reference`: unique, `WYA-` + 6 hex characters, the bank-transfer description;
  - `excuse`, `excuse_declined`, `created_at`, `paid_at`, `resolved_at`.
- unique (`event_id`, `guest_id`): one debt per guest per event; late-cancel and no-show are mutually exclusive.
- Indexes on (`guest_id`, `status`) and (`host_id`, `status`).
- No direct writes.

### photos
- **Use case:** the shared album.
- **Columns:**
  - `id`: **generated by the client**, so the storage path is known before upload;
  - `event_id`, `user_id`;
  - `path`, `thumb_path`;
  - `width`, `height` (> 0);
  - `created_at`.
- Indexes on (`event_id`, `created_at desc`) and (`event_id`, `user_id`).
- Rows are written **only by `add_photo` and `delete_photo`**.

### private schema
- **Use case:** helper functions that RLS policies need, but which the API must not expose.
- Usage is granted to `authenticated`; the schema is not exposed over REST.

## 4. Access control

### 4.1 Access tiers (the mental model)

| Who | Can |
|---|---|
| Logged out | Only `get_invite_preview(code)`: title, date, host name, cover, theme, whether the host approves joins, and whether the link still works. **Never the address.** |
| `requested` (asked to join, 8.1) | Nothing about the event except the invite preview; the host sees their name, avatar and track record to decide |
| Any other RSVP row (`invited`, `yes`, `no`, `maybe`) | See the event (minus the address), people on it, the guest list subset (Going and Maybe only), and the album |
| `yes` or `maybe` | Chat; on pledge events, also see the address |
| `yes`, not marked absent, inside the window | Add album photos |
| Host | Everything on their event: notes, invite code, all RSVPs, debts, attendance, removing guests, deleting any photo |

### 4.2 Private helpers
- **The helpers:** `is_event_host`, `is_event_guest` (any RSVP status except `requested`), `can_chat` (host or
  yes/maybe), `shares_event_with` (skips `requested`, except that a host can see who's asking), `has_open_debt`, `can_add_photos`, `can_view_photos`, `obligation_for(id, role)`.
- **Pure helpers:** `cutoff_at`, `normalize_payid`, `album_limits()` (30 per person, 300 per event; one place to raise
  for a paid tier), and `album_event(path)`, which returns null instead of erroring, because storage policies see every
  bucket's rows.
- **How they're defined:** stable, `security definer`, `search_path=''`, execute for `authenticated` only.
- **Why:** policies on `events` and `rsvps` refer to each other, and these helpers avoid infinite RLS recursion.

### 4.3 Table policies

| Table | Read | Write |
|---|---|---|
| profiles | Self, or `shares_event_with` | Self |
| events | Host, or `is_event_guest` | Host inserts, updates and deletes (can't transfer an event) |
| event_invites | Host | Trigger; limits via `set_invite_limits` |
| event_personal_invites | Host, or whoever made the link | RPC only |
| rsvps | Self, or the host of the event | Update own (status and note, never back to `invited`); no insert or delete |
| chat_messages | `can_chat` | Insert own `text`/`image` when `can_chat` (column grant: no `data`, no `created_at`) |
| poll_votes | `can_chat` | RPC only |
| chat_reads | Own | Own |
| notifications | Own | Update `read_at` only |
| payment_methods | Own | RPC only |
| obligations | Guest or host of the debt | RPC only |
| photos | `can_view_photos` | RPC only |

### 4.4 RPC catalogue
All are `security definer` with `search_path=''`, executable by `authenticated` only except `get_invite_preview`.
Each checks its caller and raises plain-language errors with SQLSTATEs (42501 permission, P0001 rule, 22023 input,
plus hints such as `OPEN_DEBT`, `PAST_CUTOFF`, `ALBUM_FULL`, `YOUR_LIMIT` that the app branches on; Phase 8 hints are
lowercase codes: `event_full`, `invite_expired`, `invite_used_up`, `join_pending`, `rate_limited`, `poll_closed`).

| Domain | RPC | Rule and why |
|---|---|---|
| Invites | `get_invite_preview(code)` | anon allowed; never returns the address. Also returns `requires_approval` and `link_status` (`open | expired | used_up`), and works for personal links |
| Invites | `accept_invite(code)` | Refuses removed guests. Anyone already on the event just gets the event id back. New people: checks expiry (`invite_expired`) and uses (`invite_used_up`) under a row lock, counts the use, and creates the RSVP as `invited`, or `requested` when the host approves joins. Personal links are single-use and skip approval |
| Invites | `set_invite_limits(event, expires_at, max_uses, requires_approval)` | Host only (8.1) |
| Invites | `approve_join(event, user)`, `decline_join(event, user)` | Host only. Approve: `requested` → `invited`, Activity `join_approved`. Decline: removes the request and blocks asking again with that link (like `remove_guest`) |
| Invites | `create_personal_invite(event, label)` | Host, or a guest while re-sharing is on; 50 a day; returns a one-time code |
| Invites | `get_invite_code(event)` | The host always; guests only when `allow_guest_invites` is on |
| Guests | `get_guest_list(event)` | Host: everyone, with notes, pledge, attended and `reliability` (jsonb, in the same call because the 30-guest stress test showed 30 separate requests). Guests: Going and Maybe rows only, other columns null |
| Guests | `remove_guest(event, user)` | Host only; deletes the RSVP and records the removal; existing debts stay |
| Chat | `get_my_chats()` | Chats you host or are yes/maybe in, last message (image-only shows "📷 Photo"), unread count, newest first |
| Chat | `mark_chat_read(event)` | Invoker |
| Chat | `create_poll(event, question, options[], multi)` | Anyone who can chat; 2–6 options of 1–60 characters; question 1–120; 10 polls per event per hour. Posts a `poll` card (8.2) |
| Chat | `vote_poll(message, option_ids[])` | Replaces your votes (an empty list takes your vote back); one option unless `multi`; refused once closed (`poll_closed`); per-person advisory lock |
| Chat | `close_poll(message)` | The poll's starter or the host |
| Chat | `get_poll_results(message)` | Votes per option in order, voter ids (visible to the chat, like WhatsApp polls), `closed` |
| Chat | `post_bot_message(event, text, data)` | **Service role only**: how the assistant's Edge Functions will reply (8.10) |
| Activity | `mark_notifications_read()` | Invoker; marks all read |
| Address | `get_event_addresses(uuid[])` | The host always; guests on non-pledge events; guests answering yes or maybe on pledge events |
| Pledges | `set_payid(value)` | Normalises and validates mobile `+614…`, email, or ABN (checksum) |
| Pledges | `remove_payid()` | Refused while someone owes you (R9); change instead |
| Pledges | `release_pledges(event)` | R4(a): clears `pledge_cents` and notifies; the app also sets the mode to `none` |
| Pledges | `record_attendance(event, absent[])` | From the start until 7 days after. Full-list semantics. Creates `no_show` debts for pledged absentees; re-ticking deletes non-paid no-show debts |
| Pledges | `claim_paid(id)` | Guest; a no-op if already paid (double tap) |
| Pledges | `dispute_payment(id)` | Host; paid → disputed |
| Pledges | `submit_excuse(id, text)` | Guest; once per debt (R7); 1–500 characters |
| Pledges | `resolve_excuse(id, accept)` | Host; accept → waived, decline → owed with `excuse_declined` |
| Pledges | `waive_obligation(id)`, `waive_all(event)` | Host |
| Pledges | `get_payment_instructions(id)` | Guest, only while open: host name, PayID, amount, reference |
| Pledges | `get_my_obligations()` | Both roles, with the other person's name |
| Pledges | `get_reliability(user)` | Self, or a host the user has an RSVP with. Returns attended, counted (marked plus late cancels) and open debts |
| Pledges | `process_pledge_deadlines()` | Callable on purpose: it only acts on what's already due, and the tests call it |
| Album | `add_photo(event, id, w, h)` | Derives the paths itself, requires both files to exist, takes a per-event advisory lock, enforces the caps |
| Album | `delete_photo(id)` | Uploader or host; returns the paths for the app to delete |
| Album | `get_album(event)` | Photos plus uploader, `can_add`, `my_count`, limits, opens/closes |
| Album | `get_my_albums()` | The Photos tab: albums you can view that have photos or are open; 6 newest thumbnail paths |
| Tests | `clear_test_notifications(since)` | `@wya.test` accounts only; deletes only the caller's own test-event items. Narrow on purpose: no service key on laptops, no change to the product rule |

### 4.5 Storage policies

| Bucket | Public? | Path | Write | Read |
|---|---|---|---|---|
| `avatars` | Yes | `<uid>/avatar`, fixed name, upserted; the URL gets `?v=<ts>` | Own folder: insert, update, delete (update was needed for iPhone upserts) | By URL; listing limited to your own folder |
| `event-images` | Yes | `covers/<uid>/<ts>`, `venues/<uid>/<ts>-<i>`, `chat/<uid>/<ts>` | Own folder | By URL; listing limited to your own folder |
| `album` | **No** | `<event>/<uid>/<id>.jpg` and `_thumb.jpg`; 5 MB; JPEG only | Own folder, and `can_add_photos` | Own files, or `can_view_photos`, through **1-hour signed URLs** |

- In the album bucket, the owner or the host can delete.
- **Why owners always see their own files:** storage only deletes files you can select, so this keeps cleanup possible
  after an event is deleted or the uploader is removed.

## 5. Business rules

### 5.1 Invites
- The share text and link are `https://wya.expo.app/invite/<code>`, built from `EXPO_PUBLIC_WEB_URL`. Why the web URL:
  `wya://` only works if the app is installed, and `localhost` is useless when texted to a friend.
- A logged-out visitor sees a themed preview, then "I'm in — create account" or "I already have an account". Both carry
  `returnTo=/invite/<code>`.
- After auth, the app returns to the invite, which calls `accept_invite` and then opens the event.
- The host can remove a guest, and that guest can't rejoin through the link.
- **Who can get in (8.1), in the event form:** a guest limit; when the link expires (never, at the start, in 7 days);
  how many times it can be used; "Approve people who join"; and the existing re-share switch.
- **Approve to join:** the invite page says "Ask to join"; after signing in the person sees "Asked to join — Hannah will
  let you know"; the host gets `join_requested` in Activity and an "Asking to join" group in the guest list with Let in
  / Decline.
- An expired or used-up link shows that on the invite page, while still offering sign-in for people already on the
  event.

### 5.2 RSVP
- **Statuses:** I'm in (`yes`), Maybe, Can't go (`no`), plus `invited` and `requested`. The guest can add a note for
  the host.
- **Guest limit:** the RSVP card shows "N spots left"; when full, I'm in shows "This event is full" and Maybe still
  works.
- **On I'm in:** confetti and a success haptic, as a small reward for committing.
- **The guest list** is grouped Going, Maybe, Not going and No answer yet. Guests see only Going and Maybe.

### 5.3 Pledges
**Decisions D1–D8**

| # | Decision |
|---|---|
| D1 | The PayID lives on the profile |
| D2 | The amount is set per event (default $5) |
| D3 | "I've paid" is trusted; the host can dispute |
| D4 | Unpaid debts show on the reliability record **and** block RSVPs to that host's events |
| D5 | I'm in → Can't go after the cutoff counts as a flake |
| D6 | The host marks no-shows |
| D7 | A Maybe carries no pledge; Maybes are reminded, then become Can't go at the cutoff |
| D8 | Australia and PayID only |

**Edge cases R1–R13**

| # | Rule |
|---|---|
| R1 | The cutoff is relative to the start, so it moves with the event |
| R2 | Each guest keeps the amount they agreed to |
| R3 | Turning pledges on later doesn't pledge guests already Going; they're asked to confirm I'm in again |
| R4 | Turning pledges off: the host chooses to release everyone, or keep existing pledges |
| R5 | Mark attendance from the start until 7 days after; unmarked means came |
| R6 | A guest with a debt can open that host's events but can't say yes or maybe |
| R7 | One excuse per debt |
| R8 | $1–$50 |
| R9 | You can't remove your PayID while owed |
| R10 | Guests see their own record |
| R11 | No Maybe after the cutoff |
| R12 | Deleting an event forgives its debts |
| R13 | A new event defaults to pledge mode once the host has a PayID, at their last amount (handled in the app) |

**Mechanics (triggers on `rsvps`)**
- **BEFORE status update:**
  1. A debt to this host blocks yes and maybe (hint `OPEN_DEBT`).
  2. Maybe after the cutoff on a pledge event is refused (hint `PAST_CUTOFF`).
  3. Yes on a pledge event with no pledge yet sets `pledge_cents = deposit_cents`.
  4. Leaving yes before the cutoff clears the pledge (free).
- **AFTER status update:** yes → no after the cutoff with a pledge creates a `late_cancel` debt.
- **Status triggers fire even when the value is unchanged.** That's how "tap I'm in again" assigns a pledge (R3).
- **Events triggers:**
  - `deposit_mode = 'pledge'` without a PayID is refused;
  - not-pledge → pledge sends `pledge_added` to unpledged Going guests.

**The cron job** `process_pledge_deadlines` runs every 15 minutes:
- reminds each Maybe once, within 24 h of the cutoff;
- at the cutoff, sets Maybe to `no` and sends `maybe_expired`.

**Debt state machine**

| From | To | How |
|---|---|---|
| (new) | owed | Trigger or attendance |
| owed, disputed | paid | `claim_paid` |
| paid | disputed | `dispute_payment` |
| owed, disputed | excuse_pending | `submit_excuse`, once |
| excuse_pending | waived | Excuse accepted |
| excuse_pending | owed | Excuse declined |
| any open | waived | Waive one, or waive all |
| non-paid no-show | deleted | The host re-ticks the guest |
| any | deleted | The event is deleted |

**Reliability.** "Came to X of Y", where Y counts marked events plus late cancels. Hosts see it in the guest list; you
see your own under You. "Owes money" is a separate flag.

### 5.4 Who came? (attendance)
- Host only, inside the window.
- Everyone Going starts ticked; the host unticks no-shows.
- The same form also updates attendance later.

### 5.5 Payment card ("You owe Hannah $5")
- Shows the PayID and the `WYA-xxxxxx` reference, each with a copy button, plus the bank steps.
- Buttons: "I've paid" and "I have an excuse".
- Appears on the event page and as a "Needs you" card.
- **Host's Pledges panel:**
  - sorted excuse_pending, disputed, owed, paid, waived;
  - actions: accept or decline an excuse, "Didn't get it", "Let them off", "Let everyone off".

### 5.6 Address gating
- On pledge events, only the host and yes/maybe guests see the address. Non-pledge events are unaffected.
- **Why:** the address is the reward for committing.
- **Enforcement:** the column grant plus `get_event_addresses`. The app merges addresses in with `withAddresses()`.
- **UI when hidden:**
  - event page: "Address hidden / RSVP to see the address", with no Directions button;
  - home card: the venue name, otherwise "Address hidden".

### 5.7 Album
**Who can add**
- The host, plus Going guests who aren't marked absent.
- From the start until 30 days after.
- Before the start: "The album opens when the party starts". After the window, view and delete only.

**Who can view.** Everyone with an RSVP.

**Limits**
- 30 per person, 300 per event.
- 1600 px JPEG plus a 400 px thumbnail, both re-encoded on the device, which strips GPS.
- Uploads go one at a time, to be gentle on phone memory.
- The picker's selection limit equals the photos left.
- Partial failures can be retried.

**Moderation**
- Photos appear straight away.
- Owners delete their own photos; the host can delete any.
- Deleting an event removes its album files first, because the host's right to delete them goes with the event.

**Live updates**
- Inserts reload the album, debounced to 1.5 s.
- Deletes are applied by id: Realtime DELETE events can't be filtered and carry only the primary key.

**Viewer**
- Swipe between photos; shows who added each one and when.
- Save: the photo library on phones, a download on the web.
- Stays on the current photo when new ones arrive.

### 5.8 Activity and notifications
**The 17 types**

| Group | Types | Sent to |
|---|---|---|
| Joining and RSVPs | `joined`, `rsvp` | Host |
| Event changes | `event_updated` (time, place or name changed), `event_cancelled` (written before the delete) | Guests not answering no, and not `requested` |
| Pledges on or off | `pledge_added`, `pledge_released` | Guests |
| Debt to the guest | `pledge_owed`, `payment_disputed`, `excuse_resolved`, `debt_waived` | Guest |
| Debt to the host | `payment_claimed`, `excuse_submitted` | Host |
| Maybes | `maybe_reminder`, `maybe_expired` | The Maybe guest |
| Album | `photos_added` | Host and Going guests, except the uploader |
| Asking to join (8.1) | `join_requested` (to the host), `join_approved` (to the person let in) | As named |

`photos_added` is **one unread row per person per event**, updated in place with the count and uploaders, so a busy
album doesn't flood anyone's Activity.

**Read state**
- An item is read when tapped, or with "Mark all read". Opening Activity alone doesn't mark items read, so the bell keeps
  meaning "something you haven't looked at".
- Activity groups items into Today and Earlier and bolds the actor and the event.

### 5.9 Chat
- Host plus yes/maybe guests. Live via Realtime.
- Text and images. Image flow: pick, upload to `chat/<uid>/`, insert with `image_path`; if the insert fails, delete the
  file.
- Tapping an image opens a full-screen swipeable lightbox.
- The Chats tab lists every chat you're in with unread counts. Opening a chat marks it read. Cards preview as
  "📊 Poll: …", "💸 Split: …", "🗓 Plan", and wya's replies as "wya: …"; wya's replies count as unread.
- **Message kinds (8.0):** the chat draws `text`, `image`, `poll`, `bot` and `system`. Kinds this version can't draw
  yet (`split`, `plan` until 8.3 / 8.9) say "Update wya to see this message". wya's replies show the logo and "asked by
  Gary".
- **Slash commands (8.2):** parsed in the app (`lib/commands.ts`), each calling its own database function. Typing `/`
  lists the commands you can use (some will be host-only); `/help` explains them; a typo (`/pol`) suggests the closest
  one and keeps the text to fix. Today: `/poll [question?] A / B / C` (a `:` also ends the question; commas work when
  there's no `/`) and `/help`. Only commands that work are offered; the rest join `COMMANDS` as their items ship.
- **Poll card:** question, options with bars and voter names, live updates, single choice (tap again to take your vote
  back) or multi, and Close for the starter or the host.

## 6. Realtime and scheduled jobs

**Realtime publication:** `chat_messages`, `notifications`, `photos`, `poll_votes`.

| Channel | Listens to | Scope |
|---|---|---|
| `chat:<event>` | Message inserts and updates (a poll closing), vote inserts (filtered by event) and deletes (unfiltered; the primary key includes `message_id`) | Only while the chat is open |
| `album:<event>` | Photo inserts and deletes | Only while the Photos tab is open |
| `unread:<uid>` | Your notification inserts, plus chat inserts (RLS limits these to your chats) | Badge refresh |

- **Every channel gets a unique name** (`freshChannel` in `lib/realtime.ts`). `supabase.channel(name)` returns the
  existing channel if one with that name is still registered, and `removeChannel()` finishes asynchronously, so an effect
  re-subscribing quickly got the old, already-subscribed channel and `.on()` threw. The name is only a label; filters
  decide what a channel receives.

**pg_cron:** `wya-pledge-deadlines` (`*/15 * * * *`) and `wya-rate-limit-cleanup` (daily), registered idempotently.

## 12. Deliberate improvements over the current build

These keep the same behaviour while fixing things found during the review.

| # | Change | Why |
|---|---|---|
| 1 | Index `chat_messages (event_id, created_at desc)` | `get_my_chats` and chat loads sort this way. **Done in 8.0** |
| 2 | Default `chat_messages.created_at` server-side and don't grant it to clients | Clients could backdate messages. **Done in 8.0** (column insert grant) |
| 3 | Retry on an obligation `reference` collision | A 6-hex unique reference can collide, and the insert would fail |
| 4 | `release_pledges` also sets `deposit_mode = 'none'` in the same transaction | Today the app must make a second call |
| 5 | Block removing a PayID while the host has a live pledge event (not just open debts) | Otherwise a guest who later owes gets a null PayID |
| 6 | Soft-remove guests (keep the RSVP history, mark it removed) | Removing a guest today deletes their attendance history and so their reliability |
| 7 | Shrink chat images like the album (1600 px) and clean up chat, cover and album files on event delete (Edge Function or queued job) | Today chat images are about 1.5 MB, and event-image files are orphaned when an event is deleted |
| 8 | Theme role `onStatusStrong` instead of the raw `#FFFFFF` in the RSVP buttons | The design-system rule |
| 9 | Explicit `auth.uid() is not null` checks in every RPC | Defence in depth; today some rely on execute grants alone |
| 10 | Keep migration history in sync with file names (apply with the CLI, or repair) | MCP-applied versions don't match the files |
| 11 | A "Preparing…" state before uploads; a timeout on iOS confirm dialogs | Known UX gaps |

## 13. Gotchas to design around

**Database**
- Auth triggers run with the auth service's `search_path`: schema-qualify names and set `search_path=''`.
- PostgREST embeds only along foreign keys: add the second FKs to `profiles`.
- Use `array_append`, not `text[] || 'literal'`.
- `.maybeSingle()` for rows that might not exist.
- `create policy if not exists` doesn't exist in Postgres.
- Changing a function's returned columns needs `drop function` first.

**Storage**
- Deletes only work on files the caller can select: owners must always see their own files.
- Storage policies see every bucket's rows: never cast a path segment straight to uuid.
- SQL deletes on `storage.objects` orphan the real files.

**Realtime**
- DELETE events can't be filtered by column and carry only the primary key.
- `supabase.channel(name)` reuses a channel that's still registered, and `removeChannel()` is asynchronous: give every
  subscription a unique name (`freshChannel`), or a quick re-subscribe throws "cannot add `postgres_changes` callbacks
  … after `subscribe()`".

**Web**
- The `single` output ignores `+html.tsx`: inject meta tags after export.
- Image-picker URIs are `blob:`: take the type from `mimeType`.
- `Alert.alert` does nothing on web.
- A Reanimated `entering` animation goes invisible if the style changes mid-animation: put layout styles on a wrapper.
- Save `null`, not `''`, for empty optional fields (RN Web "unexpected text node").

**Native**
- Fonts must load before the splash hides.
- React Native #58970: `TEXT_FIX`.
- The iOS date picker fires on every wheel move: close on Done.
- Android alerts show at most 3 buttons.
- SDK 57 uses `expo/fetch` on native.
- The iOS 18.4 simulator has a QUIC hang: use the iOS 27 simulator.
- CocoaPods needs `LANG=en_US.UTF-8`; Metro needs Watchman.
- University Wi-Fi isolation: use a phone hotspot with `REACT_NATIVE_PACKAGER_HOSTNAME`.
- The tab bar must be absolutely positioned, or the navigator reserves space and clips pages.
- No SVG or text-masking library is installed: rings are drawn with dots (`DotRing`), gradient text falls back to a
  flat colour on phones, and gradients use React Native's `experimental_backgroundImage` (not yet checked on a device).
